Two ways to run it · same content

Course track

Days 1–20 are instructor-led teaching (about 2 h) plus a guided lab (about 3 h). Days 21–30 are project studio time with mentor office hours.

Internship track

The same content, delivered as work. Interns join squads, take tickets and get code reviews from Day 1, and pick up real work from Day 21.

Ground rules
  1. Every day ends with something committed to GitHub
  2. Pull requests need one reviewer before merging
  3. Every tenth day (Days 10, 20, 30) has a checkpoint: quiz, demo or review
  4. Never commit API keys; use environment variables
  5. Interns who fall behind get a catch-up lab, not extra lectures

The plan assumes 30 working days (Monday to Saturday, about 5 weeks). For a strict 30 calendar days, run all 7 days a week with Sundays as lighter self-paced lab days, or compress the plan to about 24 working days by merging the lighter days.
